# 发布边界（Publish Boundary）· 战例与模板

任何「有发布动作」的项目，在写第一篇文档之前，必须先分清**对外层**与**对内层**。这是某静态托管项目用一次真实事故换来的：doc 契约建好后，多个内部文件漏在发布根被公网直读。

## 一、事故回顾（示例）

**现象**：`curl` 发布域名，`README` `docs/*.md` 脚本与测试快照全部返回 **200 + 真文件**；发布根的目录列表（http server 默认开）还能浏览整棵 `docs/` 树（多份技术文档 + changelog + prd）。

**根因**：线上是**整目录静态托管**——放进发布根的任何文件公网都能下载；点文件（`.env.local`）只是被 WAF 规则挡住，**规则一变即漏，不能当保护**。

**清理（已实操验证）：**
- ❌ **单纯「重新发布」清不掉**：发布是「复用同一沙箱 + 叠加上传」，**不同步删除**存量文件（实测重发后存量文件一个没少）。
- ✅ **有效做法 = 同名占位覆盖**：在发布根重建同名路径、写占位文本（带特征串如「此文件已移出发布目录」）→ 发布覆盖 → 删本地占位。实测全部被冲掉。
  - 占位特征串让暴露探测能把「已中和的占位」与「真内容外泄」区分开（`PLACEHOLDER` / `LEAK`）。
  - 占位无法再靠发布删除（叠加语义）→ 线上长期留一批无害占位；要彻底清空只能 `unpublish` + 重新 `deploy`（未采用）。
  - ⚠️ 删本地占位时**按绝对路径逐个核对前缀**，别误删同名真实目录（`项目根/docs/` 与发布根内 `docs/` 极易混淆）。

## 二、先立边界（建契约的第一步）

画两区图，把边界钉成 AGENTS.md 不变量：

| 层 | 放什么 | 公网可见 | 谁改 |
|---|---|---|---|
| 对外层（发布根/产物） | `index.html` + `assets/`（JS/CSS/图片/字体） | ✅ 直读+列表，一直挂着 | 发版脚本 |
| 对内层（项目根） | AGENTS/README/CHANGELOG/docs/scripts/快照/凭据/备份 | ❌ 绝不进对外层 | 人+AI |

**铁律不变量（直接抄进 AGENTS.md）：**

> 发布根只放 `index.html` + `assets/`；`AGENTS.md` / `README` / `CHANGELOG` / `docs/` / `scripts/` / `*.json` 快照 / `.env*` / 备份 一律放项目根，**绝不进发布根**。同名目录（`项目/docs/` vs `发布根/docs/`）是最大陷阱，靠本条兜底。

## 三、发布后必跑：暴露探测

CDN 按路径缓存、忽略 query → 验证必须带**全新的随机 query**（同一路径连续请求会 HIT 旧副本误判）。一条请求 + 唯一随机参数才稳定 `MISS` 到源站。脚本要点：
- 列发布根下所有路径；
- 对 `README` / `docs/` / `*.sh` / `*.json` / `.env*` 判越界；
- 占位特征串命中 → 标 `PLACEHOLDER`（已中和）；真内容命中 → 标 `LEAK`（P0）。

## 四、落地检查清单

- [ ] 画了「对外层 / 对内层」两区图，写进 AGENTS.md 不变量。
- [ ] 发布根里搜不到 `docs/` `README` `*.sh` `*.json` `.env*`（跑过暴露探测）。
- [ ] 目录地图同时画出两层，同名目录不会被误推进发布根。
- [ ] 老项目：先 `curl` 查线上是否已泄露内部文件，漏了先清理（同名占位覆盖）再建契约。

# AGENTS.md 强制契约 · 写法指南与实战范例

AGENTS.md 是「改代码前必读」的契约文件，放在仓库根目录。它的作用不是写漂亮文档，而是**把会出事的硬约束显式化、可拦截**。

## 一、核心不变量（Core Invariants）怎么列

每条不变量必须满足三点：
1. **可验证**——改完能对照检查（如「发版必须用路径版本号」）。
2. **会出事**——违反它真的会产线事故，不是风格偏好。
3. **可拦**——AI/人读到它就会停下自查，而不是绕过。

反面例子（不合格）：「代码要写得干净」「注意性能」。→ 不可验证、不可拦。
正面例子（合格）：「发版禁止用 `?v=` query 刷新缓存，必须用 `assets/v<版本>/` 路径级版本号」→ 可验证、违反会 CDN 混包白屏、可拦。

## 二、改动↔文档强制对照表

在不变量之后，必须有一张表把「改哪类代码 → 必须同步哪份文档 + 是否写 changelog」钉死。这是契约能落地的关键——光列不变量，AI 还是会「改完不补文档」。

格式示例：

| 改动类型 | 必须同步的文档 | 必须写 changelog |
|----------|----------------|------------------|
| 改发版流程 / 版本号 | `docs/02-release.md` | ✅ |
| 改前端核心层（core.js 等） | `docs/03-frontend.md` | ✅ |
| 改数据库表 / RPC | `docs/04-database.md`、`docs/05-rpc.md` | ✅ |
| 改业务口径（收益/消耗/余额） | `docs/06-biz-rules.md` | ✅ |
| 改数据流 / 导入 | `docs/07-data-pipeline.md` | ✅ |
| 任何踩坑 | `docs/08-pitfalls.md` | 视影响 |
| 新增页面 / 接口 | `docs/03-frontend.md` + README 索引 | ✅ |

## 三、实战范例：某静态托管仪表盘项目（不变量示例）

> 下面是从某真实项目提炼的契约**示例**，作为适配模板——换项目时按自己领域的「会出事的约束」重写，不要照抄。项目名、业务字段、CDN 厂商、具体脚本名均已泛化。

```
# AGENTS.md · <项目名> 强制契约

本项目任何代码改动前，必须先读此文件并遵守以下核心不变量。
违反任一条即视为破坏项目，须立即停下修正。

## 核心不变量（Core Invariants）

1. 发版必须用路径级版本号 `assets/v<版本>/`，禁止用 `index.html?v=版本` 刷新——
   CDN 按路径缓存、忽略 query string，?v= 会让新旧资源混包导致白屏/函数缺失。

2. 数据结构变更必须跨版本兼容：访客可能拿到「新页面脚本 + 旧核心脚本」混合包，
   改字段时保留旧键（如同时写 `ym` 与 `from/to`），别假设所有人跑最新代码。

3. 旧版本目录 `assets/v<旧>/` 与扁平 `assets/*.js` 不得删除——
   它们兜着 CDN 仍在发的旧入口页，删了会整页白屏。

4. 数据聚合一律走 SQL 函数 + rpc()，返回 TABLE 不返回标量；
   加列建 `_v2` 后缀函数，禁止 DROP 重建（会动到线上正在跑的旧函数）。

5. 新建表必须显式 GRANT 给需要访问的角色（按你项目的 RLS/授权模式）；
   漏 GRANT 会拿到形似策略失效的权限错误（如 42501）。

6. 业务分类的主判据 = <你的权威主判据，如「用户名是否命中某名册」>，不是易浮动的副信号
   （如「有没有提成」）；副信号只降级为健康度提示。

7. 余额/汇总数据只能从权威源（如控制台导出）获取，不能用公式反推
   （公式用于核对，不用于生成）。

8. 配置/补录的加载器只做类型校验，不做业务过滤；不认得的条目交给解析函数判空，
   且丢弃必须在界面上可见（静默丢数据 = 用户看到「信息丢失」）。

9. 不要手动导「当天的半天日志」进数据表——
   脚本按「当天行数>0 就跳过」，导了半天会让次日自动任务跳过该天、后半天永久丢失。

10. 改数据前先建备份表（如 _bak_YYYYMMDD），避免无回滚点。

11. 改任何功能必须同步更新对应文档 + 写一条 changelog（见改动↔文档对照表）。
    「以后补」不被接受——文档契约是核心不变量。

12. 发布边界：发布根只放 `index.html` + `assets/`，docs/ 与脚本/凭据/备份绝不进发布根；
    同名目录是最大陷阱，靠本条兜底（详见 references/publish-boundary.md）。
```

# 文档契约工作流 · 详细步骤

本文件是 SKILL.md 的放大版，提供可逐条执行的细节。分「新项目开局」与「老项目补课」两条路径。

## A. 新项目开局（从第一天就有契约）

1. **建骨架**：仓库根建 `AGENTS.md`、`CHANGELOG.md`；建 `docs/` 目录与 `docs/README.md`。
2. **写 AGENTS.md**：列初始不变量（哪怕只有 3–5 条，随开发增补）+ 改动↔文档对照表。
   初始不变量从「技术选型里的硬约束」来：发版方式、数据兼容策略、安全模型、聚合/查询口径。
3. **拆文档**：每定下一块设计就写一篇 `docs/NN-主题.md`（架构、发版、前端、数据库、业务口径、数据流、踩坑、路线图）。
4. **起 changelog**：每次提交/发版写 `docs/changelog/YYYY-MM-DD.md` 一条。
5. **固化习惯**：在 AI 的系统约定里写「改代码前先读 AGENTS.md」，让契约自动生效。

## B. 老项目补课（零文档/文档过期）

1. **摸清现状**（关键，先做）：
   - 盘点仓库结构、读残留规格（PRD/README/记忆日志）。
   - **核对真实状态**：云数据库用 MCP 工具（`db_list_tables`/`db_exec_sql`/`db_describe_table`）查表数、行数、RLS、GRANT；前端读真实 `index.html`/`core.js` 拿加载顺序与页面清单；跑命令拿真实版本号。
   - ⚠️ 记忆/旧文档的数字常过期。**引用数字一律带查询时间**（如「差额 +$100.44，2026-09-23 17:13」）。发现安全缺口（如某表 RLS 全关、anon 有增删改查）直接登记为 P0，不擅自改库。
   - 🆕 **先查发布边界是否已被打破**：`curl` 发布域名下的 `README`/`docs/`/`*.sh`/`*.json`/`.env*`，200 返回真文件即已泄露——按 `references/publish-boundary.md` 用「同名占位覆盖」清理并登记 P0，不擅自改库。
2. **建 AGENTS.md**：从真实状态里提炼不变量（见 agents-contract-guide.md）。
3. **搭 docs/**：把大 PRD 移入 `docs/prd/` 归档并写 `prd/README.md`（列已知不一致 + 明确不做）；其余拆成小文件。
4. **补 changelog**：按记忆/版本号倒推补写近几天的 `docs/changelog/YYYY-MM-DD.md`，顶层 `CHANGELOG.md` 做总览。

## C. 拆分原则（渐进式披露）

- **一篇一主题**：架构、发版、前端、数据库、业务口径、数据流、踩坑、路线图各成一篇。
- **序号排序**：`01-` `02-` … 两位序号，便于文件树排序与 README 引用。
- **250 行天花板**：单篇 >250 行就拆 `主题-a.md`/`主题-b.md` 或子目录。超大文件（如 PRD 946 行）必须归档不堆在 docs 根。
- **索引唯一**：`docs/README.md` 是全局地图，列出每篇链接 + 一句话说明 + 维护规则（命名/行数上限/超长拆分）。
- **链接相对路径**：保证 VS Code / GitHub / 任意渲染器都能跳转。
- **现状快照标时间**：表数量、RPC 数量、页面数量、余额核对数字等，都写在架构/业务文档里并标查询时间。
- **沟通产物单列**：决策单/验收清单/修改意见不要散落项目根，统一进 `docs/decisions/` 与 `docs/acceptance/`（见 docs-README 模板），与规格文档分离且不对外。

## D. 维护纪律（契约真正起作用的地方）

- **改完即同步**：每完成一次功能改动，立即更新对应 `docs/NN-*.md` + 写一条 changelog。不积压成「以后补」。
- **对照表强制**：AGENTS.md 的改动↔文档表是执行依据，改 X 必须动 Y。
- **不变量随演化增补**：踩出新坑 → 立刻补一条不变量，让后来者不再踩。
- **偏差不过夜**：发现文档与实际不符，当场修，不让偏离累积。
- **每日收尾自查**：改动是否都写了 changelog？文档是否同步？新不变量是否进了 AGENTS.md？

## E. 常见陷阱（来自真实项目）

1. **凭记忆写文档**：记忆数字过期（如余额核对差额记错、户数分布对不上）→ 一律查真实库再写，引用带时间。
2. **CDN 缓存导致发版「看起来没生效」**：按路径缓存、忽略 query，必须用路径级版本号，别用 `?v=`。根路径 `/` 有独立缓存条目，发布不主动失效。
3. **数据格式不兼容**：访客可能拿到新旧混合包 → 改结构保留旧键。
4. **verify 脚本漏检文件**：发布校验清单（如 `verify.sh` 的 FILES）必须与 `index.html` 的引用一一对应，新增页面立刻补进校验清单。
5. **加载器做业务过滤**：不认得的条目被静默丢光，用户看到「信息丢失、重填存不住」→ 加载器只做类型校验。
6. **安全缺口未登记**：某表 RLS 关闭 + anon 有增删改查，是全库唯一敞口 → 登记 P0 给修复 SQL，但数据库变更需用户确认后再做。
7. **docs/ 误进发布目录被公网抓取**：静态托管整目录可下载、目录列表可浏览；点文件（`.env`）只靠 WAF 挡、规则一变即漏。→ 发布根只放 `index.html`+`assets/`，docs/ 与脚本/凭据/备份全在对内层；发版后跑暴露探测（见 `references/publish-boundary.md`）。
